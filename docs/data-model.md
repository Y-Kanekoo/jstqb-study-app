# データモデル

すべての日時はPostgreSQLで`TIMESTAMPTZ`、端末でISO 8601 UTCとして保持します。IDは原則UUIDです。

専用content-control internal suspend RPCのglobal transactionが行うのは、対象`question_versions.status='suspended'`とDB `frozen_at`、全catalog streamのtombstone/revision、strict operation receipt、durable `content_suspension_operations`、`content_suspension_targets`と全`content_suspension_target_members`の確定だけです。target predicateは停止時点の実効値に限定し、未invalidated・graded attempt、各examの最新実効revision、各offline resultの最新result/feedback exact pair、未invalidated session itemだけを、不変commit時計の`source_committed_at <= frozen_at`で固定します。過去revision、invalidated/not-graded attempt、旧offline pair、停止後到着行を除外します。このtransactionで複数userのsession/attempt/projectionを更新しません。commit直後からdraft/answer/exam finalizer/feedback/catalog/owned-session/bootstrapを含む全RPCはglobal statusを再検証します。suspended版は本文・正答・feedbackを0件またはcontent-null tombstoneへ収束させ、selection basis原本とlifecycle/hashは変更しません。停止後に到着したanswer eventは選択履歴付き`not_graded_suspended` attemptとinvalidationを同一transactionでappend・ACKし、fanout対象外とします。

bootstrapの全sectionはowner/preview acceptanceと参照versionをlockしてstatusを確定します。`attempt-history`は確定attemptと訂正・無効化の実効履歴、`exam-history`はterminalとresult revision、`session-lifecycle`はcompleted/abandoned/invalidated、`offline-reference-history`は正式成績と分離した参考結果、全result revision、全feedback revisionをappend-only ID/revision chainのまま保持します。suspended版、fanout pending版、acceptance-revoked版はcatalog/session item/selection basisのsafe contentをNULL tombstoneにし、同版feedbackを返しません。clientはcatalog tombstoneまたはfact ID/hash付き`session.item-invalidated`適用時に同版content/feedback cacheを同一local transactionでpurgeします。selection basis原本・選択順・lifecycle/hashは変更しません。`profile` rowにはprofile revision、`daily-projection`には`correct_count`を含めます。正答集合、問題解説、choice解説はbootstrap rowへ含めません。

user scopedな全version依存read/writeの唯一のlock順は`user advisory shared/exclusive → question version UUID byte昇順 shared/exclusive row lock → aggregate/event advisory → session/attempt row → projection/materialized row`です。通常のsession pin、draft、answer、finalizer、feedback、catalog/owned-session、restore materializationはversion shared lock取得後にstatusを判定します。global suspend transactionだけは対象versionをexclusive lockし、user lockを取得せずにglobal status、catalog tombstone、immutable target memberを確定してcommitします。user別fanoutは後続の別transactionで上記user scoped順序に従います。回答commitが先ならその後suspend、suspend commitが先ならgraded attempt・正答feedback 0です。

公開schemaの全テーブルでRLSを有効にし、migrationテストで越権拒否を検証します。

authenticated/anonはquestions、question_versions、choices、answer keyを直接SELECTできません。全RPCでPUBLIC EXECUTEをREVOKEします。通常のclient RPCはanonからもREVOKEしてauthenticatedだけへgrantし、例外は固定allowlistのruntime capability safe RPCだけをanon/authenticatedへgrantします。

M2 migrationは初期schemaの`own_sessions_all`、`own_drafts_all`、`own_attempts_insert`、`own_states_insert/update`、`own_bookmarks_all`、`own_issues_insert`とprofile直接UPDATEを同一transactionで撤回し、authenticatedから全学習materialized tableのINSERT/UPDATE/DELETEをREVOKEします。legacy互換期間に残すwriteは、owner限定`sync_events` INSERTと、所有者・型・payloadを検証してshared user lockを取るcanonical triggerだけです。profileはgeneration、expected revision、shared lockを要求する専用RPCで更新します。

全learner mutationは`user_id`から導出した同一advisory keyのshared transaction lockを、session/attempt等のrow lockより先に取得します。対象にはlegacy trigger、v2 sync、selection basis、session/exam、draft/answer、finalizer、訂正・無効化、profile、personal acceptance/activate/revoke、bookmark/note/issueと管理issue更新を含めます。bootstrap/exportと本人状態readも同keyのshared lockでgenerationを検証します。restore finalizeとaccount deletion workerだけが同keyのexclusive lockを取得し、互いに並行実行しません。lock取得後に認証主体、owner、current data generation、reauth target generationを再検証し、不一致時はlive stateを変更しません。

user scopedな全経路のlock取得順は`user advisory shared/exclusive -> question version UUID byte昇順 shared/exclusive row lock -> aggregate/event advisory -> session/attempt row -> projection/materialized row`へ固定します。version非依存経路だけversion段を空集合として通過します。event replayでも先にuser lockを取り、version/event/attempt lockからuser lockへ逆行しません。global suspendだけはversion exclusive lock中にuser lockを取らず、fanoutを別transactionへ分離します。複数userを扱う管理処理はuser UUID byte昇順に一人ずつ処理し、同一transactionで複数user lockを保持しません。二接続concurrency試験で順序違反、deadline跨ぎ、restore/delete/suspend競合がdeadlockせず一意に収束することを検証します。

client向けruntime capability読取は本人データと分離した署名済みallowlist safe RPCだけです。このRPCだけはPUBLICをREVOKEした上でanon/authenticatedへEXECUTEを許可し、基礎table・内部control・ACL証跡へ到達できない固定projectionだけを返します。`runtime_capability_snapshots`のmain SHA、migration/worker version、RPC signature、ACL evidence、smoke、期限、feature依存を検証します。`content-release-v2`は署名済みruntime controlの`cryptographic_release_attestation_required`を必須入力とし、値が明示falseならD-01/P0 recent-auth、明示trueなら`cryptographic-release-attestation-v1`完備を要求し、欠落・未知値・署名不正をfalseへdefaultせずfeature OFFへ収束させます。content suspend operationは開始時の`worker_name='suspension-fanout'`、`pinned_worker_version`とruntime capability snapshot ID/hashをtarget setへAPI正本の`execution_contract_hash`で結合し、receiptもこれへ一致させます。欠落・差替え時は該当content operationをfail-closedにします。`runtime_controls`や内部証跡tableをanon/authenticatedへ直接SELECTさせません。

Privileged Control Planeとlearner/contentの全基礎tableはPUBLIC/anon/authenticatedから不要権限をREVOKEし、`service_role`にも直接SELECT/INSERT/UPDATE/DELETEをgrantしません。全`SECURITY DEFINER`関数はLOGIN不能・業務table権限を必要最小にしたneutral NOLOGIN function-owner roleが所有し、関数実行中のdefiner identityをcaller識別に使用しません。client RPCはPUBLIC/anon/service_role/internal専用roleからEXECUTEをREVOKEしauthenticatedだけへgrantし、JWTの`auth.uid()`からownerを導出してnull、client `userId`、cross-ownerを拒否します。internal RPCはPUBLIC/anon/authenticated/service_role/他の専用roleからEXECUTEをREVOKEし、用途ごとのexact専用NOLOGIN execution roleだけへgrantします。isolated workerのLOGIN roleは対応する一execution roleへの`SET ROLE`権限だけを持ち、基礎table/function-owner role/他execution roleへのmembershipを持ちません。internal RPCはACLに加えてclaim済みjob/member、lease owner/expiry/fencing tokenを検証し、`auth.uid()`やclient由来user IDへ依存しません。両RPC群は`search_path`固定、完全修飾名、strict DTO、規定lock、reauth binding、operation auditを必須にします。runtime capabilityは例外として固定allowlist safe RPCだけをanon/authenticatedへgrantし、job状態、download URL、receiptは用途別authenticated safe RPCだけから返します。

owner review ACL matrixの対象はexact `begin_owner_question_review_session_v2`, `get_owner_question_review_v2`, `submit_owner_question_blind_answer_v2`, `reveal_owner_question_review_v2`, `hide_owner_question_review_v2`, `complete_owner_question_review_audit_v2`, `record_owner_question_review_v2`の7関数です。全関数でPUBLIC/anon/service_role/internal roleをREVOKEし、authenticatedのうちdeployment owner本人だけをJWT allowlistで許可します。allowlist外の一般learnerとadmin/運用者も同じ非識別拒否にし、admin roleやservice credentialをowner代理として扱いません。
