# 端末保存の原子性と競合検知

## 対象

PR #7 の `2cde48d` を基点に、F-02・F-05 の端末保存失敗と、同期処理が端末更新に重なる場合を修正した。

回答、進捗、Outbox は一つの学習スナップショットとして保存する。Web は IndexedDB の readwrite transaction、iOS / Android は SQLite の exclusive transaction で旧値との比較と書込みを行う。別タブが先に保存した場合は競合エラーとし、再読込を案内する。

状態と Outbox は端末への書込みが成功した後に画面へ反映する。書込み失敗時は元の状態を保持し、後続操作は再試行できる。通常演習の次問移動は確定済み回答を必要とする。模試で選択の保存に失敗した場合は、再選択するまで移動と提出を止める。

保存キューには選択、回答、同期 ACK、受信イベント、復元を同じ順序で通す。ACK は送信時に確認した event ID のみを削除し、後から追加されたイベントを残す。受信イベントが未送信のドラフト、メモ、ブックマーク、進捗と衝突した場合、その手前まで処理して cursor を止め、次回同期で再取得する。競合は設定画面に表示する。スナップショットの復元失敗も元の状態を残す。メモ保存に失敗した入力は画面を離れても一時状態に保持し、再保存できる。

## 検証

- 保存失敗後の回答と Outbox の不変性、再試行
- 選択失敗と後続回答の順序、模試の移動・提出停止
- 同期 ACK と新しい選択の交錯、受信イベントとの競合
- 別タブ書込みの拒否と再読込、バックアップ復元失敗
- `pnpm check:any`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、Web export
